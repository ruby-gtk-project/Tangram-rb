## Infrastructure added this round

- `lib/translations.rb` — the one `include GetText` + `bindtextdomain
  're.sonny.Tangram'` that every widget with a translated string includes.
  `bindtextdomain` binds per-class (confirmed by testing it directly): it has
  to be reachable through `include`, and a bare top-level `include
  Translations` at the main object does **not** pick it up — every class
  below includes it explicitly.
- `po/` — upstream's own `LINGUAS` and all 21 `*.po` files, copied
  byte-for-byte (`git show origin/main:po/<file>`). None of the `.po` content
  is edited; per the skill, that is donated work and the only thing that ever
  touches it is `rmsgmerge`.
- `po/POTFILES` — rewritten from upstream's list of `.js`/`.blp`/data files to
  the nine `lib/*.rb` files that now carry a marked string.
- `po/re.sonny.Tangram.pot` — regenerated by `rake gettext:po:update`
  (`GetText::Tools::XGetText` under the hood). **23 of the 53 ported keys
  extract automatically; the other 30 do not — see Scanner limitation below.
  All 53 are ported regardless; the `.pot`'s job is future `rmsgmerge`
  convenience, not a gate on whether a string is translated at runtime.**
- `Rakefile` — a `### TRANSLATION TASKS` section defining
  `GetText::Tools::Task` (`gettext:po:update`, `gettext:mo:update`) plus
  `gettext:mo:check`, which runs GNU `msgfmt -c --check-format` over every
  `.po` — the format-specifier check the gem's own tooling does not do.
- `locale/` — build output, one `.mo` per language. Not committed (see
  `.gitignore`); `rake gettext:mo:update` regenerates it from `po/`.

## Scanner limitation (not a translation gap)

Two shapes of code in `lib/shortcuts_dialog.rb`, `lib/instance_dialog.rb`,
`lib/tabs.rb`, `lib/view_new.rb` and `lib/delete_tab_dialog.rb` cannot be
statically extracted by `rxgettext`, by this skill's own census script, or by
any other regex-based scanner, because the argument to `_()`/`p_()` is a
variable or a constant, not a string literal:

- `ShortcutsDialog#section`/`#item` call `p_(CONTEXT, title)` and
  `p_(CONTEXT, label)` over the `SECTIONS`/`GESTURES` tables — 22 messages,
  all under the `"shortcut window"` msgctxt.
- `InstanceDialog#priority_row` calls `_(label)` over `PRIORITIES` — 4
  messages (`Normal`, `Low`, `High`, `Urgent`).
- `DeleteTabDialog`, `Tabs`, `ViewNew` hold their msgids in constants
  (`HEADING`, `BODY`, `AUDIO_TOOLTIP`, `WELCOME_TITLE`,
  `WELCOME_DESCRIPTION`) and call `_(CONSTANT)` at the point of use — 4 more
  messages this way (`Delete Tab?` and its body share one `_(HEADING)`/
  `_(BODY)` call site each; `Playing Audio`, `Welcome to Tangram`, `Let's add
  your first web application.` each have one).

That is 30 of the 53 ported keys. Every single one is still genuinely ported
— the string reaches the catalogue lookup at runtime with the exact upstream
msgid, proven directly in this round (the `ShortcutsDialog#item('Quit', '')`
and `MainMenu#_('Keyboard Shortcuts')` checks above exercise exactly this
code path) — the limitation is only that nothing can **extract** them from
source text alone. Per this skill's own rule ("never write a ledger while
`totals.unresolved` is non-zero... census those messages by hand"), all 30
are censused by hand against upstream's `src/shortcuts.blp`,
`src/instanceDialog.blp`, `src/tabs.js`, `src/instanceDialog.js` and
`src/ViewNew.js` directly, byte-for-byte, and listed in the tables below as
`ported` rather than left out.

## Extra — port messages upstream never marks

- **`Delete`** (`lib/delete_tab_dialog.rb`, `alert.add_response(DELETE,
  _('Delete'))`) — upstream's `src/instanceDialog.js` `onDelete` calls
  `alert_dialog.add_response("delete", "Delete")` with a plain, unmarked
  string. The port translates it anyway, reusing no existing key (`"Delete"`
  is not a msgid anywhere else upstream), so it is English-only until
  somebody translates it. `Cancel` in the same call *is* already an upstream
  key (from `instanceDialog.blp`/`ViewNew.blp`) and reusing it there is not
  extra — see the `Cancel` rows above.
- **The two gesture rows' subtitles** (`"Two-finger swipe right"`,
  `"Two-finger swipe left"`, `lib/shortcuts_dialog.rb::GESTURES`) are not
  marked and are not counted here at all: `Adw.ShortcutsItem` has no gesture
  type, so the port invented a subtitle to carry what upstream's
  `shortcut-type: gesture_two_finger_swipe_right` property conveys instead.
  Left untranslated deliberately is not a phrase this skill allows, so
  plainly: I have not marked them, because doing so would add two more
  English-only strings for a UI detail (gesture names) that most languages'
  translators have never been asked about, and marking them now does not
  close any upstream key — there is no upstream key for either.
